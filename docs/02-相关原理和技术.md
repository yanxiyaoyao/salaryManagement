## 2. 核心原理

### 2.1 JWT认证机制

JWT（JSON Web Token）是一种用于身份验证的开放标准（RFC 7519）。

**工作流程：**

```
用户登录 → 验证用户名密码 → 生成JWT → 返回Token
   ↓
客户端存储Token → 每次请求时在Header中携带Token
   ↓
服务器验证Token → 提取用户身份信息 → 处理请求
```

**JWT结构：**

```
Header.Payload.Signature

- Header：包含算法信息（如HS256）
- Payload：包含用户ID等声明信息
- Signature：使用密钥对前两部分签名
```

**优势：**

- 无状态：服务器不需要存储会话信息
- 跨域友好：可用于跨域请求
- 移动友好：适合移动应用
- 安全性高：使用密钥签名，难以伪造

### 2.2 RESTful API设计原则

REST（Representational State Transfer）是一种架构风格，强调使用HTTP方法操作资源。

**核心原则：**

- **资源导向**：每个URL代表一个资源
- **HTTP方法**：使用GET、POST、PUT、DELETE等方法表示操作
- **无状态**：每个请求都包含完整的信息
- **统一接口**：提供一致的API设计

**示例：**

```
GET    /api/transactions      - 获取交易列表
POST   /api/transactions      - 创建新交易
GET    /api/transactions/:id  - 获取单个交易
PUT    /api/transactions/:id  - 更新交易
DELETE /api/transactions/:id  - 删除交易
```

### 2.3 MVC架构模式

系统采用MVC（Model-View-Controller）架构模式：

- **Model**：数据模型和业务逻辑（SQLAlchemy ORM）
- **View**：用户界面（React组件）
- **Controller**：请求处理和响应（Flask路由）

**优势：**

- 关注点分离：各层职责清晰
- 易于测试：各层可独立测试
- 易于维护：代码组织清晰
- 易于扩展：新功能易于添加

### 2.4 Redux状态管理

Redux是一个可预测的状态管理库，采用单一数据源原则。

**核心概念：**

- **Store**：全局状态容器
- **State**：应用状态
- **Action**：描述发生了什么的对象
- **Reducer**：纯函数，根据Action更新State
- **Dispatch**：发送Action的方法

**数据流：**

```
View → Dispatch Action → Reducer → Update State → View
```

**优势：**

- 可预测性：状态变化可追踪
- 易于调试：可记录所有状态变化
- 易于测试：Reducer是纯函数
- 性能优化：避免不必要的重新渲染

## 3. 数据库设计原理

### 3.1 关系型数据库

系统使用SQLite关系型数据库，遵循以下设计原则：

**范式化设计：**

- **第一范式（1NF）**：属性不可再分
- **第二范式（2NF）**：消除非主属性对主键的部分函数依赖
- **第三范式（3NF）**：消除非主属性对主键的传递函数依赖

**关键设计：**

- **主键**：唯一标识每条记录
- **外键**：维护表间关系
- **索引**：提高查询性能
- **约束**：保证数据完整性

### 3.2 数据模型

系统包含以下主要数据模型：

```
User（用户）
├── id: 主键
├── username: 用户名（唯一）
├── password_hash: 密码哈希
├── nickname: 昵称
├── email: 邮箱
├── phone: 电话
├── avatar: 头像
└── 时间戳

Category（分类）
├── id: 主键
├── name: 分类名称
├── type: 分类类型（expense/income）
├── color: 颜色
└── 时间戳

Transaction（交易）
├── id: 主键
├── type: 交易类型（expense/income）
├── amount_cents: 金额（分）
├── currency: 货币
├── occurred_on: 发生日期
├── category_id: 分类ID（外键）
├── note: 备注
├── tags: 标签
└── 时间戳
```

## 4. 前端架构设计

### 4.1 组件化设计

系统采用React组件化设计，遵循以下原则：

- **单一职责**：每个组件只负责一个功能
- **可复用性**：组件应可在多个地方使用
- **可组合性**：组件可组合成更复杂的组件
- **可测试性**：组件应易于单元测试

### 4.2 路由设计

使用React Router v6实现前端路由：

```
/ (根路由)
├── /login (登录页)
├── /register (注册页)
└── /admin (受保护的后台)
    ├── / (仪表盘)
    ├── /categories (分类管理)
    ├── /transactions (交易流水)
    ├── /statistics (统计分析)
    ├── /profile (个人中心)
    └── /settings (系统设置)
```

### 4.3 状态管理设计

使用Redux Toolkit管理全局状态：

```
Store
├── auth (认证状态)
│   ├── token
│   ├── user
│   └── isAuthenticated
├── tabs (标签页状态)
│   └── tabs[]
└── 其他业务状态
```

## 5. 安全性设计

### 5.1 密码安全

- **哈希存储**：使用werkzeug.security进行密码哈希
- **盐值**：自动添加盐值，防止彩虹表攻击
- **验证**：使用check_password_hash验证密码

### 5.2 认证安全

- **JWT签名**：使用密钥对Token签名
- **过期时间**：Token设置1小时过期时间
- **HTTPS**：生产环境应使用HTTPS

### 5.3 跨域安全

- **CORS配置**：仅允许特定来源的请求
- **预检请求**：浏览器自动发送OPTIONS请求进行验证

## 6. 性能优化策略

### 6.1 后端优化

- **数据库索引**：为常用查询字段添加索引
- **查询优化**：使用关联加载避免N+1查询
- **缓存**：对频繁访问的数据进行缓存
- **分页**：大数据集使用分页查询

### 6.2 前端优化

- **代码分割**：使用动态导入实现路由级别的代码分割
- **组件懒加载**：使用React.lazy实现组件懒加载
- **状态优化**：避免不必要的重新渲染
- **资源优化**：压缩图片和CSS/JS文件
