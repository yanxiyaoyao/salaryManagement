# 个人开支记账管理系统 - 需求分析

## 1. 功能需求

### 1.1 用户管理

#### 1.1.1 用户注册

**需求描述：** 新用户可以通过注册页面创建账户

**功能需求：**

- 用户输入用户名和密码
- 系统验证用户名是否已被占用
- 系统验证密码强度（可选）
- 注册成功后自动跳转到登录页
- 注册失败显示错误提示

**数据需求：**

- 用户名：字符串，长度3-50，唯一
- 密码：字符串，长度6-128

#### 1.1.2 用户登录

**需求描述：** 用户可以通过用户名和密码登录系统

**功能需求：**

- 用户输入用户名和密码
- 系统验证用户名和密码
- 登录成功返回JWT Token
- 系统自动存储Token到本地存储
- 登录失败显示错误提示

**数据需求：**

- 用户名：字符串
- 密码：字符串

#### 1.1.3 用户登出

**需求描述：** 用户可以登出系统

**功能需求：**

- 用户点击登出按钮
- 系统清除本地Token
- 系统跳转到登录页

#### 1.1.4 个人中心

**需求描述：** 用户可以查看和修改个人信息

**功能需求：**

- 显示用户基本信息（用户名、昵称、邮箱、电话）
- 支持修改昵称、邮箱、电话
- 支持上传头像
- 支持修改密码
- 修改成功显示提示信息

**数据需求：**

- 昵称：字符串，长度0-50
- 邮箱：字符串，有效的邮箱格式
- 电话：字符串，长度0-20
- 头像：图片文件

### 1.2 交易管理

#### 1.2.1 交易记录列表

**需求描述：** 用户可以查看所有交易记录

**功能需求：**

- 显示交易列表（分页）
- 支持按类型筛选（收入/支出）
- 支持按分类筛选
- 支持按日期范围筛选
- 支持按关键词搜索
- 支持排序（按日期、金额等）
- 显示交易详情（日期、金额、分类、备注）

**数据需求：**

- 分页：每页20条记录
- 排序：默认按日期降序

#### 1.2.2 新增交易

**需求描述：** 用户可以添加新的交易记录

**功能需求：**

- 选择交易类型（收入/支出）
- 输入金额
- 选择分类
- 选择交易日期
- 输入备注（可选）
- 输入标签（可选）
- 验证数据有效性
- 保存成功显示提示

**数据需求：**

- 交易类型：expense/income
- 金额：正数，最多两位小数
- 分类：必选
- 日期：YYYY-MM-DD格式
- 备注：字符串，长度0-500
- 标签：字符串，多个标签用逗号分隔

#### 1.2.3 编辑交易

**需求描述：** 用户可以修改已有的交易记录

**功能需求：**

- 加载交易详情
- 支持修改所有字段
- 验证数据有效性
- 保存成功显示提示

#### 1.2.4 删除交易

**需求描述：** 用户可以删除交易记录

**功能需求：**

- 显示删除确认对话框
- 支持软删除（标记deleted_at）
- 删除成功刷新列表

### 1.3 分类管理

#### 1.3.1 分类列表

**需求描述：** 用户可以查看所有分类

**功能需求：**

- 显示分类列表
- 按类型分组显示（收入/支出）
- 显示分类颜色
- 显示分类下的交易数量

#### 1.3.2 新增分类

**需求描述：** 用户可以创建自定义分类

**功能需求：**

- 输入分类名称
- 选择分类类型（收入/支出）
- 选择分类颜色
- 验证分类名称唯一性
- 保存成功显示提示

**数据需求：**

- 分类名称：字符串，长度1-50，同类型内唯一
- 分类类型：expense/income
- 颜色：十六进制颜色代码

#### 1.3.3 编辑分类

**需求描述：** 用户可以修改分类信息

**功能需求：**

- 加载分类详情
- 支持修改分类名称和颜色
- 不能修改分类类型
- 验证数据有效性

#### 1.3.4 删除分类

**需求描述：** 用户可以删除分类

**功能需求：**

- 检查分类是否被使用
- 如果被使用，提示用户无法删除
- 删除成功刷新列表

### 1.4 统计分析

#### 1.4.1 概览统计

**需求描述：** 显示财务概览数据

**功能需求：**

- 显示本月收入总额
- 显示本月支出总额
- 显示本月结余
- 显示本月交易笔数
- 支持切换时间范围（本月、本年、自定义）

#### 1.4.2 分类统计

**需求描述：** 显示按分类的统计数据

**功能需求：**

- 显示各分类的支出/收入金额
- 显示各分类的占比（饼图）
- 支持按时间范围筛选
- 支持导出数据

#### 1.4.3 趋势分析

**需求描述：** 显示收支趋势

**功能需求：**

- 显示日/周/月的收支趋势（折线图）
- 显示收入和支出的对比
- 支持按时间范围筛选

#### 1.4.4 标签统计

**需求描述：** 显示按标签的统计数据

**功能需求：**

- 显示各标签的交易笔数
- 显示各标签的总金额
- 支持点击标签快速查看相关交易

### 1.5 系统设置

#### 1.5.1 基本设置

**需求描述：** 用户可以配置系统基本设置

**功能需求：**

- 设置默认货币
- 设置默认分类
- 设置系统语言
- 设置时间格式

#### 1.5.2 数据管理

**需求描述：** 用户可以管理自己的数据

**功能需求：**

- 导出数据为CSV/Excel
- 导入数据（计划中）
- 备份数据（计划中）

#### 1.5.3 账户安全

**需求描述：** 用户可以管理账户安全

**功能需求：**

- 修改密码
- 查看登录历史
- 管理登录设备

### 1.6 导航功能

#### 1.6.1 浏览器标签页风格导航

**需求描述：** 提供浏览器标签页风格的面包屑导航

**功能需求：**

- 用户导航到不同页面时自动创建标签页
- 最多显示10个标签页
- 支持点击标签页快速导航
- 支持关闭单个标签页
- 支持右键菜单（关闭其他、关闭所有）
- 支持工具栏快速关闭所有标签页

**标签页映射：**

- /admin → 概览
- /admin/categories → 分类管理
- /admin/transactions → 交易流水
- /admin/statistics → 统计分析
- /admin/profile → 个人中心
- /admin/settings → 系统设置

## 2. 非功能需求

### 2.1 性能需求

| 指标 | 目标值 |
|------|--------|
| 页面加载时间 | < 3秒 |
| API响应时间 | < 500ms |
| 数据库查询时间 | < 100ms |
| 支持并发用户数 | 100+ |

### 2.2 可靠性需求

- **可用性**：系统可用性 ≥ 99%
- **数据完整性**：交易数据不丢失
- **容错能力**：系统异常时能正确处理
- **恢复能力**：系统故障后能快速恢复

### 2.3 安全需求

- **身份认证**：使用JWT进行身份认证
- **数据加密**：密码使用哈希加密存储
- **访问控制**：用户只能访问自己的数据
- **SQL注入防护**：使用ORM防止SQL注入
- **CSRF防护**：使用CORS和Token验证

### 2.4 易用性需求

- **界面友好**：提供直观的用户界面
- **操作简单**：常用操作不超过3步
- **错误提示**：清晰的错误提示信息
- **帮助文档**：提供在线帮助文档

### 2.5 可维护性需求

- **代码质量**：遵循编码规范
- **代码注释**：关键代码添加注释
- **文档完整**：提供完整的技术文档
- **易于扩展**：系统架构支持功能扩展

### 2.6 兼容性需求

- **浏览器兼容**：支持Chrome、Firefox、Safari、Edge等主流浏览器
- **操作系统兼容**：支持Windows、Linux、macOS
- **响应式设计**：支持桌面、平板、手机等不同屏幕尺寸

## 3. 用例分析

### 3.1 用户注册用例

```
参与者：新用户
前置条件：用户未登录
主流程：
1. 用户进入注册页面
2. 用户输入用户名和密码
3. 系统验证输入数据
4. 系统创建新用户
5. 系统显示注册成功提示
6. 系统跳转到登录页面

异常流程：
- 用户名已被占用：显示错误提示
- 输入数据无效：显示验证错误
```

### 3.2 记录交易用例

```
参与者：已登录用户
前置条件：用户已登录
主流程：
1. 用户进入交易管理页面
2. 用户点击"新增交易"按钮
3. 用户填写交易信息
4. 系统验证数据
5. 系统保存交易记录
6. 系统显示成功提示
7. 系统刷新交易列表

异常流程：
- 分类不存在：显示错误提示
- 金额格式错误：显示验证错误
```

### 3.3 查看统计数据用例

```
参与者：已登录用户
前置条件：用户已登录，存在交易数据
主流程：
1. 用户进入统计分析页面
2. 系统加载统计数据
3. 系统显示各种统计图表
4. 用户可以切换时间范围
5. 系统更新统计数据

异常流程：
- 无交易数据：显示空状态提示
```

## 4. 数据流分析

### 4.1 用户登录数据流

```
用户输入 → 前端验证 → 发送请求 → 后端验证 → 生成Token → 返回Token
   ↓
前端存储Token → 设置请求Header → 跳转到首页
```

### 4.2 交易记录数据流

```
用户输入 → 前端验证 → 发送请求 → 后端验证 → 保存数据库 → 返回结果
   ↓
前端更新状态 → 刷新列表显示
```

### 4.3 统计数据流

```
用户选择时间范围 → 发送请求 → 后端查询数据库 → 计算统计数据 → 返回结果
   ↓
前端渲染图表 → 显示统计结果
```
